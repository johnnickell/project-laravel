# Adopt Released Fight Packages and Retire Certification

## Outcome

Deliver one independently reviewable PR that makes the starter an application consumer of Fight Common 1.2.0
and Fight AccessControl 0.4.0 without upstream-certification machinery. This slice covers all acceptance criteria
of [T-00006](../tickets/00006-TICKET.md); parent completion still requires explicit evidence and review.

Package adoption and certification retirement stay together: the current receipts, lane locks, and warning
exception pin the old candidate. Do not temporarily recertify the new releases just to split the change.

## Scope

- In scope: Composer constraints/lock and installed-package verification; candidate alias/warning-exception
  removal; compatible application-owned composition; certification receipt/hash artifacts, lowest/latest lanes,
  complete-provider probes, and certification-only/meta-test retirement; meaningful retained behavioral tests;
  public contract documentation; current setup/instructions and affected planning reconciliation.
- Likely change boundaries: `composer.json`, `composer.lock`, `app/Providers/FightServiceProvider.php`, relevant
  configuration, `etc/evidence/framework-support/`, `scripts/framework-support-lane`,
  `scripts/validate-composer.php`, `bin/build`, `tests/`, `phpunit.xml`, and current application documentation.
  Classify each binding/test by its actual application purpose, not merely its filename.
- Preserve Laravel, Eloquent, Pint, `App\` mapped to `app/`, the HTML homepage, meaningful application integration
  contracts, inward dependencies, and exact 100% owned-production statement coverage.
- Out of scope: T-00007's running-stack PHP build redesign; new authentication, permissions, persistence, or API
  journeys; full WF-002 capability mapping; upstream changes/publication; Common 2.0; MCP; copied package source;
  retiring-interface shims; and a replacement certification subsystem.
