# Bind Laravel Workflows and Canonical Evidence

## Outcome

Deliver one discoverable Laravel-native binding for shared engineering workflows and canonical evidence.
Maintainers and agents can resolve supported capabilities, local substitutions and applicable independent
reports without guessed provider paths or weakened acceptance. This completes the binding/report/handoff
acceptance criteria of [TICKET-00013](../tickets/00013-TICKET.md) after TASK-00009's coherent naming migration.

## Scope

- In scope: `planning/agents/workflow-binding.md`, explicit root AGENTS.md reference, affected local entrypoints
  and current handoffs; adopted EPIC/TICKET/TASK names and Board/Wayfinder paths; supplied provider capability
  resolution; Laravel substitutions; canonical Review/QA paths/formats, subject matching and report ownership;
  canonical evidence/coordinator storage exceptions to dated scratch; realistic handoff walkthroughs.
- Preserve repository commands, Laravel/Eloquent/Pint, native entrypoints, `App\` mapped to `app/`, MySQL
  direction, public package ownership, `var/cache/`, exact owned-production coverage, required hosted and public-contract
  proof and existing routing/delivery safeguards. TICKET-00007/TICKET-00011 retain successor-gate policy ownership.
- Out of scope: copying shared skills or private implementation; provider/harness changes; global installation
  or enrollment; a report validator/generator or replacement report subsystem; report rewriting by builders or
  Land; product behavior, gate redesign and repository-wide prospective closeout rollout owned by TICKET-00014.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected effects |
| --- | --- | --- | --- | --- |
| Resolve the local workflow and authority | Supplied provider-owned skills; Build by TASK ID when available | Binding, target context and actual capability metadata | N/A: operational instructions | Correct local target/capability is resolved; unavailable capability produces a precise prerequisite hold |
| Hand implementation to Review, then QA and delivery | Existing supported stage invocations; no new business command | Canonical subject, findings, evidence and continuation | N/A | Each stage receives applicable evidence without inferring acceptance or broader execution authority |
| Resolve evidence from an isolated worktree | Existing Git/common-directory inspection | Main/base worktree and canonical Review/QA identities | N/A | One canonical location survives disposable-worktree cleanup; ambiguity stops the handoff |

## Validation and permissions

No runtime business actor, target permission, input payload or business event is introduced. The binding grants
no execution/publication authority: use the selected workflow's scope. Resolve provider resources only from
actual harness/operator-supplied metadata; do not guess an installation path, silently substitute capabilities,
install tools or scan unrelated private runs. Preserve existing Build ledger identities and consumed revision
allowance on continuation.

Require repository, TASK, requirements revision, full base/head OIDs, working-tree state, independence and findings
for report applicability. A matching TASK number, old PASS, clean Git status or chat summary alone is not enough.
Missing/stale/mismatched evidence, uncertain subject bridge, unsafe symlink resolution or an ambiguous/unwritable
canonical base produces a named incomplete handoff. Never edit independent reports to make the scenario pass.
