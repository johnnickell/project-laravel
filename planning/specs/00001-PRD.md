# Framework Starter Product and Walking-Slice Acceptance

## Problem Statement

A new Laravel starter project needs governed boundaries: explicit Fight Common and Fight AccessControl Composer dependencies, Laravel-native service providers, container bindings, routing, HTTP middleware, and presentation composition. Fight Common and Fight AccessControl must remain public Composer packages only.

## Solution

The bootstrap establishes a governed hello-world foundation with Docker-backed tooling, a canonical `./bin/build` gate, hosted CI, and public-source guidance. The application composes Fight packages through Laravel service providers and renders a home page through Nginx and PHP-FPM.

## Implementation Decisions

- Repository-local planning, architecture, triage, and public-source guidance are canonical.
- Docker-backed Composer, PHPUnit, lifecycle, and build wrappers exist.
- `./bin/build` is the single noninteractive local and hosted gate.
- Laravel owns service providers, container bindings, routing, HTTP, security, persistence, queues, realtime, and presentation.
- MIT, contribution, and security policies are present.

## Testing Decisions

- `./bin/build` validates the public Composer boundary and the Laravel container-backed hello-world seam.
- Hosted CI invokes the exact same `./bin/build` command.

## Out of Scope

- Login, persistence, browser journeys, releases, tags, Packagist publication, template enablement, create-project distribution.
